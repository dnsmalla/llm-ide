# @llmide/ui-kit

One look for every web surface: design tokens as CSS variables (generated from
`schema/design/tokens.json`) and the shared presentational React components.
Private package, consumed from source. Design: `docs/kits/ui-kit.md`.

Not a feature: no server route, no data, no feature key.

## What is in it

| Piece | Where | Notes |
|---|---|---|
| Tokens (CSS) | `src/styles/tokens.generated.css` | GENERATED by `scripts/gen-design-tokens.mjs`; `--tok-color-*`, `--tok-space-*`, `--tok-radius-*`, `--tok-type-*`. `:root` = default theme, `[data-theme="dark\|light\|midnight"]` override colours only. |
| Derived colours | `src/styles/aliases.css` | `--tok-color-success`, `-warning`, `-info`, diff, gutter, editor. Mirrors `Theme.swift`; a test fails on drift. |
| Component styles | `src/styles/components.css` | Tokens only, no raw colours. Focus ring and reduced motion included. |
| Entry CSS | `src/styles/kit.css` (`@llmide/ui-kit/styles.css`) | tokens + aliases + components. |
| Themes | `src/themes.generated.ts`, `src/theme.ts` | `THEMES`, `ThemeId`, `isThemeId`, `applyTheme`. |
| Components | `src/components/*` | `Chip`, `EditorTabBar`, `FileTreeRow`, `LibrarySidebar`, `ResizableDivider`, `SectionChromeBar`, `SettingsSectionCard`, `StatusBanner`. |
| Icons | `src/icons.tsx`, `src/icons.generated.ts` | One open set (Lucide, ISC), vendored. |

## Consuming it

React 18.2+ or 19 is a peer dependency. The package exports TypeScript source, so
the consumer's bundler compiles it. Every surface does the same three things:

```ts
import "@llmide/ui-kit/styles.css";                  // 1. tokens + components
import { applyTheme, StatusBanner } from "@llmide/ui-kit";
applyTheme("dark");                                  // 2. data-theme + color-scheme on <html>
// 3. build screens from kit components and --tok-* variables; no raw colours.
```

- **Desktop (Tauri, `desktop/`)**: Vite alias `@llmide/ui-kit` -> `../ui/kit/src/index.ts`
  and `@llmide/ui-kit/styles.css` -> `src/styles/kit.css` (`desktop/vite.config.ts`),
  matching `paths` in `desktop/tsconfig.json`; `resolve.dedupe` keeps one React.
- **Phone PWA, relay web view**: same two aliases (or a `file:` / workspace dependency
  once a second package manager root exists). Per-surface CSS copies are fine for
  bundling, but they must come from the same generator and keep the `--tok-*` names:
  add the surface's path to `buildOutputs` in `scripts/gen-design-tokens.mjs`, and
  `--check` (in `make contract-gates`) then guards it.
- **Chrome extension, System view**: already use `--tok-*` CSS from the same generator;
  they can adopt components when they need one.
- Scoping a theme to a sub-tree is not supported yet: theme blocks are
  `:root[data-theme=...]`. Use one theme per document (the gallery has a switcher).

## Untrusted-output rules (relay and any surface that shows model or remote text)

The kit must stay safe to render text a model, a relay or a remote peer produced.
`tests/components.test.mjs` enforces the first four on the whole of `src/`.

1. **No raw HTML.** No `dangerouslySetInnerHTML`, `innerHTML`, `insertAdjacentHTML`,
   `document.write`, `eval`, `new Function`. Text goes in as React children (escaped).
2. **No remote-resource components.** No `<img>`, `<iframe>`, `<script>`, `<link>`,
   `<object>`, `<embed>`; no `url(http...)` or remote `@import` in CSS. A component that
   shows a remote image must be added deliberately, with its own review, not here by default.
3. **No inline event handlers or `href` built from content** inside kit components.
   Callbacks come from the host as props.
4. **Styling from tokens only.** Content cannot choose colours or classes.
5. Rendering Markdown or diagrams from untrusted text is the host's job and needs a
   sanitiser (the desktop pins `dompurify`, see `desktop/scripts/check-dompurify.mjs`).
   The kit ships no Markdown renderer.

## Accessibility

Labelled controls (every icon button has an `aria-label`), roles (`toolbar`, `tablist`,
`tree`, `separator`, `alert`/`status`), `aria-pressed` / `aria-expanded` / `aria-selected`
state, visible keyboard focus ring (`:focus-visible`, accent colour, >= 3:1 on every
theme), `prefers-reduced-motion` removes transitions and animations, `ResizableDivider`
is keyboard operable (arrows, Home, End). Colour contrast of the token pairs is tested
for all three themes (`tests/contrast.test.mjs`). Known gaps:

- Light theme `textMuted` on `body` is 4.31:1 (AA needs 4.5). It is a `tokens.json`
  value, so fixing it changes the Mac look too; it needs a design decision.
- `EditorTabBar`: `role="tab"` wraps two buttons (select and close), which a screen
  reader announces awkwardly. Restructure at the first K3 screen that uses it.
- `LibrarySidebar` and `SelectItemEmpty` carry the spike's demo content (hard-coded
  sections and counts). They are layout fixtures until Library's real data arrives (K3).

## Icons

One open set for web surfaces: **Lucide** (ISC licence, copyright Lucide Icons and
Contributors; parts derived from Feather, MIT; text in `LICENSES/lucide-ISC.txt`),
pinned at `lucide-static` **1.65.0** (exact, `package.json`). The used glyphs are
copied into `src/icons.generated.ts` by `npm run icons`, so there is no runtime icon
dependency; `tests/icons.test.mjs` fails when the file is stale. SF Symbols stay
Mac-only (they cannot ship in a web view).

## Commands

```bash
cd ui/kit
npm ci
npm test            # tokens, components (SSR), contrast, icons, gallery build
npm run type-check
npm run gallery     # writes gallery/dist/index.html: every component, theme switcher
npm run icons       # re-vendor the Lucide glyphs
node ../../scripts/gen-design-tokens.mjs   # regenerate tokens (also: make design-tokens)
```

`make test-desktop-node` runs the kit tests and type-check when `ui/kit/node_modules`
exists; `make contract-gates` runs the token drift check.

Today: DOM and token assertions (this package's tests) plus the reviewed screenshots in
`desktop/parity/`. Decision U4 asks for pixel-tolerance fixtures; that needs a headless
browser and the Mac render of the same fixture, neither of which is a light dependency.

## Rules for adding a component

Mirror a Mac component in `Core/DesignSystem`, take colours from `--tok-color-*` only,
give every control a name, a focus ring and a keyboard path, add an SSR test and a
gallery entry, and keep the untrusted-output rules above.
