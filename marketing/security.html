Security and privacy

Identity in the cloud.
Knowledge on your desk.

The account service and the workspace have different jobs. Keeping them separate is the core security decision.

What the account service stores

  • Email, display name, language and time zone.
  • Passkey public keys — never private keys.
  • Login sessions, hashed tokens and account audit events.
  • Device labels and status.

What it never stores

  • Meeting transcripts, notes or action items.
  • Source code, chats or generated documents.
  • Your Claude login or provider API keys.
  • AI prompts or model responses.

Controls in the workspace

Loopback core

The local core binds to 127.0.0.1. The desktop is the only client that starts it.

OS secret store

Provider keys and local signing secrets live in the operating system’s credential store, not in the webview.

Explicit actions

Tool calls, code edits and publishing go through approvals and protected-path rules.

Small cloud surface

The public account service has no admin UI, no core import and no AI/agent code.

Report a vulnerability

Email security@llm-ide.com. Please include reproduction steps and avoid testing against other users’ accounts or data.

Remote phone/browser access is being built as an end-to-end encrypted relay. Until that is enabled, the web client can use only the temporary desktop-host path you explicitly configure.
