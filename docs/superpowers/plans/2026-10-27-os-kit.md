# Plan: os-kit — the Agentic OS view (kit 1)

**Date:** 2026-10-27
**Status:** Approved 2026-10-27 — System view on Home (Mac), no extension tab, React in a web view
**Parent:** [kit-by-kit migration](2026-10-27-kit-by-kit-migration.md) (os-kit section)

## What the user sees

The Mac app's **Home** page becomes the **System** view when a project is open
(today Home opens the user's chosen landing page, default Explorer). No new
top-menu item. With no project open, Home still shows the Welcome screen; the
existing *Settings → Workspace → Home section* picker still lets a user choose
another landing page. The Chrome extension gets nothing for now.

```
┌ System map ───────────────────┬ Running now ─────────────────┐
│ kits on/off + health,         │ chat turn  Sonnet 5.5  [stop] │
│ delegated vs project-owned    │ meeting agent  …       [stop] │
├ Activity timeline ────────────┴───────────────────────────────┤
│ 13:02 chat turn 26.6k tok · 12:58 Box ingest 14 notes · …      │
├ Token flow ───────────────────┬ Memory & knowledge ───────────┤
│ by surface/model, cache       │ project facts, sources, code   │
│ read vs write, prefix vs      │ graph freshness, pending       │
│ transcript                    │ reviews                        │
└───────────────────────────────┴───────────────────────────────┘
```

Read-only, **no model calls**: every number comes from data the server
already records.

## Where the data comes from (K0 map, 2026-10-27)

| Panel | Source today |
|---|---|
| System map | `config.features` + `/health` checks; kit list is static (the kit table) |
| Running now | v2 chat turns (`inFlightAborts`, cancel = `POST /agent/v2/cancel`), meeting-agent runs (`listRuns`, cancel = `POST /kb/agent/stop`), live capture sessions |
| Activity | `activity` table (11 kinds, last 500 per user), `chat_sessions` |
| Token flow | `usage_ledger` (+ cache columns, endpoint, source), `turn_composition`, `turn_tool_events` |
| Memory & knowledge | `project_memory_ledger`, `sources` / `stats`, `code_graph_meta`, `review_items`, `outcomes` |

Gaps (the server cannot see these yet): Loop journal, Auto Task schedules and
history, Mac chat transcripts, Library notes on disk. **v1 shows server data
only** and labels Loop/Auto Task as "on this Mac — coming in automation-kit";
the job runner in that kit moves the state server-side, at which point it
appears here with no view change.

## Decision (confirmed 2026-10-27)

**OS-3 technology: React in a WKWebView.** **React in a WKWebView**, built once and
reused by the future desktop app (code reuse, one look via ui-kit tokens).
Cost: a Vite build step joins the Mac build and the panel is a web view.
Rejected alternative: native SwiftUI now (simpler Mac build, best Mac feel) and a
second React version for the desktop app later (two implementations).

## Revision 2 (2026-10-27): the visual Agentic OS, in the Graph section

The user reviewed the first System page (a card dashboard) and wants a far more
visual view, in the spirit of the "Rubric Agentic OS": a living graph "brain" in
the centre, a ring of recent work orbiting it, and panels around the edge.

**Placement (user decision).** Home opens the **Graph** section. The Graph
section's default page is the visual System view; a toggle switches to the
existing code graph. **Explorer** becomes an ordinary top-menu item. (A build
without `code_graph_3d` falls back to Explorer as Home — `resolveHome` already
does this.)

**Ownership (user decision).** The graph is graph-kit's domain, so the reusable
parts move into graph-kit's TypeScript side (a new `web` entry), shared by the
Mac web view now and the desktop (Tauri) app later:

| Part | Where |
|---|---|
| System graph builder: system state (kits, skills, sessions, activity, memory) + the project's code/knowledge graph → one canonical graph-kit graph | graph-kit `typescript/src/system/` |
| Orbit layout: dense 3D core (the code/knowledge graph, force/sphere) + a ring of recent items ordered by time | graph-kit `typescript/src/layout/orbit.ts` (Swift parity later, if the native view needs it) |
| WebGL renderer: point-cloud core coloured by node kind, slow rotation, ring nodes with labels, hover/click events | graph-kit `typescript/src/web/` (three.js) |
| Page, panels and bridge | LLM-IDE `ui/os-view/` (panels from OS-1 data) |
| Section switch, Home, Explorer menu item, graph data via the native bridge | LLM-IDE Mac (`Core/Contracts` seam so Code Graph embeds the System view without naming the System feature) |

**Centre "brain" (chosen by Claude, user deferred).** The open project's real
code + knowledge graph as a point cloud (nodes coloured by kind: code, docs,
tests, knowledge sources), capped for speed (largest communities kept, never
edges pruned — weighted, per the graph-kit rule). Orbit ring = recent activity
(chat turns, ingests, Loop/Auto Task runs, dispatches), clickable.

**Panels.** Left: System map (kits/health), Running now, Skills deck
(`/kb/agent/skill-library`). Right: Token flow, Memory & knowledge, Routines
(Auto Task schedule, supplied natively — Mac-only data).

**Steps.** G1 graph-kit web module (builder + orbit layout + renderer, tests,
demo page) → G2 Mac: section/Home/Explorer menu + graph data and routines over
the bridge → G3 os-view redesign around the renderer → G4 review (Sonnet per
step, Fable for the kit) → graph-kit push + version pin, then LLM-IDE push.
