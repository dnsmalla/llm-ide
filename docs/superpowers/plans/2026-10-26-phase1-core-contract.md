## Goal

Every client (Mac app, Chrome extension, the coming Tauri app) talks to the
Node core through **one written, versioned contract**, checked in CI, so a
client can never silently drift from the server. Alongside it, put the two
things the user asked to protect — **consistent appearance** and **code
reuse** — on the same footing: one source for design tokens, one generated
type layer for the TypeScript clients.

## North star: fast and few tokens

The product's main objective (user, 2026-10-26) is **speed and minimal token
use**, built by combining the best features from every source. Every task in
every phase states what it costs and saves in tokens and latency. Baseline
from the usage ledger, 2026-10-01 → 26 (billable-weighted: cache read 0.1×,
cache write 1.25×):

| Path | Turns | Avg per turn | Dominated by |
|---|---|---|---|
| `/agent/v2/stream` | 9 | 34 350 | ~125 k cached context re-read per turn |
| `/code-assist` (classic) | 4 | 19 296 | ~13.7 k setup re-written per turn (no cache reuse) |
| background (classifier, memory) | 59 | 3 099 | many small calls |

The lever is context size per turn, not model choice alone.

## Principles (apply to every task)

1. **Reuse the pattern that already works.** `schema/agent-v2/` (JSON Schema +
   fixtures) and `scripts/conformance-agent-v2.mjs` (validity, coverage,
   Swift decode-gap, roster) already gate the v2 chat wire. Phase 1
   generalises that runner; it does not invent a second mechanism.
2. **One source, generated outputs.** Specs are hand-written once per route
   group; OpenAPI, TypeScript types and the endpoint roster are generated
   from them. No hand-copied types in two clients.
3. **One look.** Design tokens move out of Swift into a shared file that
   generates both the Swift theme and the CSS tokens (Mac, Tauri, Chrome
   extension), so all three surfaces cannot drift.
4. **No behaviour change.** This phase documents and tests the server as it
   is. A mismatch found becomes a reported finding or a separate small fix
   commit, never a silent change inside a schema task.

## Scope

105 endpoints in `ALL_ENDPOINTS` (`extension/server.mjs`):
92 under `/kb/…` (agent 21, review 6, usage 5, connect 5, slack 4, plan 4,
outcomes 4, mcp 4, live 4, ingest 3, email 3, chat 3, and ~25 single
routes), plus `/agent/*` (4), `/code-assist` (2), `/chat`, `/generate-*`,
`/extract-entities`, `/agent-sdk`. Clients: 23 Mac `LlmIdeAPIClient+*.swift`
files, the Chrome extension hooks in `extension/src/`.

## Tasks

| # | Task | Output | Check |
|---|---|---|---|
| P1 | **Inventory** | `schema/http/INVENTORY.md` generated by `scripts/http-inventory.mjs`: every endpoint → method, handler file, auth, feature group, Mac callers, extension callers | the script fails if `ALL_ENDPOINTS` has a path with no handler or a client calls a path not in it |
| P2 | **Generalise the runner** | `scripts/conformance-http.mjs` sharing code with `conformance-agent-v2.mjs` (extract common validity/coverage/roster into `scripts/lib/conformance.mjs`; agent-v2 keeps passing unchanged) | `make chat-gates` still green; new runner passes on an empty schema set |
| P3–P10 | **Route-group schemas** (one task each): health/auth/meta · notes & generation (`/generate-*`, `/extract-entities`, `/chat`) · kb search/sources/ingest/connect · planning/plans/outcomes/dispatch · review · providers/routing/usage/custom · agent & code-assist (non-stream) · live/loop/issues/mcp/slack/email/activity | `schema/http/<group>.schema.json` + fixtures captured from the existing node tests (temp DB) | runner: every fixture valid, every declared field covered, every endpoint of the group has a request + response schema |
| P11 | **Server conformance in tests** | a node test that replays each fixture's request against a temp-DB server and validates the live response against the schema | `npm test` green |
| P12 | **Swift decode check** | `api-contract-lab` (executable, like `chat-contract-lab`) decoding every fixture with the Mac's `Codable` models and reporting fields Swift drops; allowlist with reasons | `make regression` runs it |
| P13 | **Generated TypeScript types** | `schema/http` → `extension/src/lib/api-types.ts` (+ the same file consumed by `desktop/` later); replace hand-written response types in extension hooks where they exist | `tsc` green; no duplicated response interfaces left (grep gate) |
| P14 | **OpenAPI + docs** | the repo already hand-maintains `docs/reference/api/openapi.yaml` with an API-coverage check in `make docs-check` — reuse it: generate it from `schema/http` (keeping its existing descriptions) instead of adding a second OpenAPI file; `SERVER_API_VERSION` bump rule documented | `make docs-check` |
| P15 | **Shared design tokens** | `schema/design/tokens.json` (the three themes, spacing, type scale, category/status colours, moved from `Theme.swift`); generators → `mac/…/Core/Platform/ThemeTokens.swift` (Theme.swift reads it) and CSS (`desktop/`, Chrome extension) | Mac app pixel-identical (screenshot diff of Library + Chat in 3 themes); `--check` gates in all three |
| P17 | **Token & speed gate** | `scripts/token-bench.mjs`: a fixed scenario set (greeting, explain one file, one small edit, one plan step) run against a temp-DB server on the cheapest capable model, recording per scenario: billable tokens, cache read/write, turns, time to first token, total time → `schema/bench/token-baseline.json`; fails when a scenario regresses > 15 % vs the committed baseline. Run on demand / nightly, not on every push (it spends tokens) | first baseline committed; a deliberate prompt bloat makes it fail |
| P16 | **CI + pre-push** | `make contract-gates` in `make regression` and CI | push gate green |

Order: P1 → P2 → P3–P10 (can run two at a time; disjoint files) → P11–P13
→ P14 → P15 (independent, can start after P2) → P16.

## Day 1

P1 (inventory) and P2 (runner generalisation); start P3 (health/auth/meta)
once P2 is reviewed.

## Out of scope

Moving Swift-only logic into the core (Phase 2), the Tauri screens
(Phase 3), the relay (Phase 4). The four Phase 0 conditions are carried into
their phases; only the design-token move (part of "one look") lands here.
