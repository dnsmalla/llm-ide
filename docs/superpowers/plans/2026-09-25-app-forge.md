# App Forge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship four kit skills (`app-forge`, `app-research`, `app-council`, `app-stack-menu`) plus a `/app-forge` CLI command that take one app idea to a built, verified app through a MiroFish-shaped staged pipeline.

**Architecture:** Pure content in the `.skills` kit (dnsmalla/agent-kit). The orchestrator skill owns a `.forge/state.json` state machine and two approval gates, and hands off to stage skills by id (`load-skill skills/<dir>` in LLM-IDE, the Skill tool in Claude Code). Build/verify reuse the kit's existing process skills. A bash contract test pins each skill's load-bearing content so edits can't silently drop a stage, gate, or guard.

**Tech Stack:** Markdown SKILL.md + YAML frontmatter, `registry.yaml`, bash tests (kit style: `tests/*.sh`), git submodule.

**Spec:** `docs/superpowers/specs/2026-09-25-app-forge-design.md`

## Global Constraints

- Every `SKILL.md` **< 24,000 chars** (Mac chat cap, `extension/llm_agent/skills/skill-library.mjs:112`).
- Frontmatter `name` == directory name; `description` starts with "Use when".
- Registry entries: `family: process`, `tools: [claude, cursor, codex, agents, gemini]`, `stacks: []`, `version: 1.0.0`.
- Hand-off ids are `skills/<dir>` (LLM-IDE `load-skill`) and skill names (Claude Code Skill tool).
- Research budget **≤ 8 searches, ≤ 6 fetches**. Council rounds default 1, **max 2**. Verify **≤ 3 fix attempts** per failing check.
- Artifacts (exact names): `seed.md research.md council.md spec.md plan.md verify.md report.md state.json` under `<app-dir>/.forge/`.
- Never write outside the confirmed target dir; never push; no global installs.
- CLI command lives in `commands/cli/app-forge.md`, linked (relative symlink) from `config/tool/claude/commands/app-forge.md` — never copied.
- Kit gates stay green: `scripts/validate.sh`, `tests/registry_integrity.sh`, `scripts/test-install.sh`.
- Kit work on branch `feat/app-forge` in `.skills`; llm-ide work on branch `feat/app-forge`. No pushes.

```bash
#!/usr/bin/env bash
# App Forge contract test — pins the load-bearing content of the four
# app-forge skills and the /app-forge command, so an edit cannot silently
# drop a stage, a gate, a budget, or a guard the design depends on.
# Spec: llm-ide docs/superpowers/specs/2026-09-25-app-forge-design.md
#
# Run: bash tests/app_forge_contract.sh   (from the kit root or tests/)
set -u

KIT_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
cd "$KIT_ROOT" || exit 1

fail=0
err() { printf 'FAIL: %s\n' "$*" >&2; fail=1; }

# has <file> <fixed-string> — assert a literal appears in a file.
has() { [ -f "$1" ] && grep -qF -- "$2" "$1" || err "$1 lacks: $2"; }

SKILLS="app-forge app-research app-council app-stack-menu"
MAX_CHARS=24000

# 1. Each skill exists, is registered, is under the Mac chat's read cap,
#    and has a "Use when" description.
for s in $SKILLS; do
    f="skills/$s/SKILL.md"
    [ -f "$f" ] || { err "missing $f"; continue; }
    grep -qE "^\s+path:\s+skills/$s\$" registry.yaml || err "registry.yaml lacks skills/$s"
    n="$(wc -c < "$f" | tr -d ' ')"
    [ "$n" -lt "$MAX_CHARS" ] || err "$f is $n chars (cap $MAX_CHARS)"
    grep -qE '^description:.*Use when|^  Use when' "$f" || err "$f description must start with 'Use when'"
done

# 2. Orchestrator: every artifact, every hand-off id in both forms, both
#    gates, resume, and the blast-radius rule.
O=skills/app-forge/SKILL.md
for a in seed.md research.md council.md spec.md plan.md verify.md report.md state.json; do has "$O" ".forge/$a"; done
for id in app-research app-council app-stack-menu writing-plans subagent-driven-development \
          executing-plans verification-before-completion systematic-debugging test-driven-development; do
    has "$O" "skills/$id"
done
has "$O" "load-skill"
has "$O" "Skill tool"
has "$O" "Gate 1"
has "$O" "Gate 2"
has "$O" "awaiting-approval"
has "$O" "save-plan"
has "$O" "Resume"
has "$O" "never the current repository"
has "$O" "3 fix attempts"
has "$O" "ask the"

# 3. Research: tool names for both hosts, budget, lanes, id scheme, fallback.
R=skills/app-research/SKILL.md
for t in web-search fetch-url WebSearch WebFetch "8 searches" "6 fetches" "UNVERIFIED" "(model knowledge)" \
         "## Entities" "## Relations" "## Gaps" "## Sources"; do has "$R" "$t"; done
for p in "[U1]" "[C1]" "[L1]" "[K1]" "[R1]" "G1" "S1"; do has "$R" "$p"; done

# 4. Council: roster, the three passes, round cap, anti-bleed guards.
C=skills/app-council/SKILL.md
for p in "Product Manager" "Architect" "UX Designer" "Security" "QA" "Skeptic" "Simulated user" "Moderator"; do has "$C" "$p"; done
for t in "Positions" "Challenge" "Synthesis" "max 2" "[opinion]" "cannot add features" \
         "Resolved conflicts" "Open questions" "skills/app-stack-menu"; do has "$C" "$t"; done

# 5. Stack menu: every stack, the six fields, the off-menu rule, probes.
M=skills/app-stack-menu/SKILL.md
for s in "Vite + React + TS" "Next.js" "FastAPI" "Hono" "Python CLI" "SwiftUI" "Expo" "Docker Compose"; do has "$M" "$s"; done
for t in "Scaffold" "Install" "Test" "Build" "Launch check" "Off-menu" "node -v" "uv --version" "swift --version" "docker --version"; do has "$M" "$t"; done

# 6. /app-forge command: file, registry entry, relative symlink for installer hosts.
CMD=commands/cli/app-forge.md
has "$CMD" "argument-hint:"
has "$CMD" "app-forge"
grep -qE 'path: commands/cli/app-forge\.md' registry.yaml || err "registry.yaml lacks commands/cli/app-forge.md"
L=config/tool/claude/commands/app-forge.md
[ -L "$L" ] || err "$L must be a symlink"
[ "$(readlink "$L")" = "../../../../commands/cli/app-forge.md" ] || err "$L must point at ../../../../commands/cli/app-forge.md"

[ "$fail" -eq 0 ] && echo "app-forge contract: OK"
exit "$fail"
```
