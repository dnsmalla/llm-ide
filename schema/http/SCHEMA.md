# HTTP endpoint contract

Machine-checked request and response shapes for the Node server's HTTP routes.
`scripts/conformance-http.mjs` gates them (`make contract-gates`).

`INVENTORY.md` (generated by `scripts/http-inventory.mjs`) lists every route in
`ALL_ENDPOINTS` and its callers. This directory holds the hand-written
specification of those routes, one group at a time.

## Layout

```
schema/http/
  <group>.schema.json            one file per route group
  _common.schema.json            shared $defs, referenced as "_common#/$defs/<name>"
  fixtures/<group>/<name>.json   one example exchange per fixture
  INVENTORY.md                   generated; do not edit
  SCHEMA.md                      this file
```

`<group>` is the route group's name (`health`, `auth`, `kb`, …). A group file and
its fixture directory share that name. `_common.schema.json` is not a group.

## Group file

```json
{
  "$defs": {
    "Item": { "type": "object", "required": ["id"], "properties": { "id": { "type": "string" } } }
  },
  "endpoints": {
    "POST /kb/items/:id": {
      "request": {
        "query":  { "type": "object", "properties": { "dry": { "type": "boolean" } } },
        "params": { "type": "object", "required": ["id"], "properties": { "id": { "type": "string" } } },
        "body":   { "$ref": "#/$defs/Item" }
      },
      "responses": {
        "200": { "type": "object", "properties": { "id": { "type": "string" } } },
        "400": { "$ref": "_common#/$defs/Error" },
        "409": { "type": "object", "required": ["error"], "properties": { "error": { "type": "string" } } },
        "204": { "x-content": "none" }
      }
    }
  }
}
```

- `endpoints` is keyed by `"<METHOD> <path>"`. The method is one of GET, POST,
  PUT, PATCH, DELETE, HEAD, OPTIONS. The path must be a literal entry of
  `ALL_ENDPOINTS` in `extension/server.mjs`.
- **Path parameters** appear as `:name` in the key, matching the roster. Name them
  as the roster does. P14 translates `:name` to the `{name}` form of the OpenAPI
  output. Do not write `{name}` in a key.
- `request` is optional. Its keys are any of `query`, `params`, `body`; any other
  key is rejected. Each part is a JSON Schema for that part.
- `responses` is required and keyed by a **numeric status code** (`200`, `404`).
  Other keys (`"ok"`, `"default"`) are rejected. Each value is one of the forms below.
- `$defs` holds named schemas, referenced as `#/$defs/<name>` within the same file.
- A `$ref` replaces its node wholesale. Siblings of `$ref` are rejected, because
  they would be ignored.

### Response forms

| Form | Declares | Fixture `response` |
|---|---|---|
| a schema | the JSON body | checked against it |
| `{ "$ref": "_common#/$defs/Error" }` | the error envelope | checked against it |
| `{ "oneOf": [ …variants… ] }` | one of several bodies | matches exactly one variant, which is then the one checked and covered |
| `{ "x-content": "none" }` | no body (for example `204`) | must be absent |
| `{ "x-content": "binary" }` | a file body | `{ "contentType", "description" }` only, both strings |
| `{ "x-content": "text", "type": "string" }` | a plain-text body | a string |
| `{ "x-content": "sse", "x-events": "schema/agent-v2/agent-v2.schema.json" }` | a server-sent event stream | an array of events, each checked against the event schema's `oneOf` variant |
| `{ "x-unspecified": "<reason>" }` | a body not yet specified | not checked; counted in the summary and listed |

A bare `{}` response is **rejected**. Either declare the body, or mark it
`"x-unspecified": "<reason>"`. The reason is printed in the run's output, so the
gap stays visible until someone closes it.

`oneOf` is supported only at the top of a response schema, not nested.

## Schema keywords

Only these keywords are accepted, plus any `x-*` extension key. Anything else fails
with the file and JSON pointer.

`type`, `properties`, `required`, `items`, `enum`, `const`, `$ref`, `$defs`,
`additionalProperties`, `oneOf`, `description`, `title`.

- `additionalProperties: true` accepts keys the schema does not name.
- `additionalProperties: <schema>` is a **map**: every key is accepted, and each
  value is checked against that schema. Paths for map values use `*` in place of
  the key (`labels.*`), so a fixture with any keys covers them.
- `type` may be an array of types (`["string", "null"]`).
- Arrays of arrays are checked to any depth.

## Extension keys

| Key | Where | Meaning |
|---|---|---|
| `x-content` | response | `none`, `binary`, `text`, or `sse` (see the table above) |
| `x-events` | response with `x-content: "sse"` | path, from the repo root, to an event schema with `oneOf` variants |
| `x-unspecified` | response | reason a body is not yet specified |
| `x-optional` | a property | the property may be absent in fixtures, so it is not required to be covered (used for `error.details`) |

## Shared definitions

`_common.schema.json` holds `$defs` used by several groups, reached as
`"_common#/$defs/<name>"`. Its definitions must be self-contained: a `$ref` inside
it would resolve against the group file that uses it, so the gate rejects one.

`$defs.Error` is the error envelope every failing route returns, in the shape that
`sendError` in `extension/core/errors.mjs` writes:

```json
{ "error": { "code": "VALIDATION_FAILED", "message": "…", "details": { } } }
```

`code` is a stable identifier clients switch on. `message` is prose. `details` is
optional, and its shape depends on the code.

## Fixture

```json
{
  "endpoint": "POST /kb/items/:id",
  "status": 200,
  "request":  { "params": { "id": "x" }, "body": { "id": "x" } },
  "response": { "id": "x" }
}
```

- `endpoint` must name an endpoint declared in a group file, and the fixture must
  sit in `fixtures/<that group>/`.
- `status` must be a status code declared under that endpoint's `responses`.
- **Every declared request part is required.** If an endpoint declares `query`, each
  fixture of it must carry `request.query`, even as `{}`. The rule exists so each
  fixture exemplifies every part the schema describes.
- `request` is omitted only for an endpoint that declares no request parts.
- `response` is checked against the form for its status (table above). Omit it only
  for a bodyless status (`x-content: "none"`).
- `description` is allowed. Nothing else beyond the keys above is.

## Checks

0. **LOAD** — every file parses (an invalid file is reported and the run continues);
   every keyword is supported; every `$ref` resolves; response keys are numeric;
   no bare `{}`. Each problem names its file and JSON pointer.
1. **VALIDITY** — each fixture's request and response match their schemas: required
   keys at every level, no undeclared keys (unless the object sets
   `additionalProperties`), types, `const`, `enum`, `oneOf` variant choice, map
   values, and array items. An SSE response is checked event by event.
2. **COVERAGE** — every field path a schema declares is exercised by a fixture.
   Request paths are exercised by any fixture of the endpoint. Response paths by a
   fixture of that status. A `oneOf` response is covered per variant: each variant
   needs its own fixture. A declared field no fixture carries fails the gate.
   `x-optional` properties are exempt.
3. **ROSTER** — every endpoint a group declares exists in `ALL_ENDPOINTS`
   (`scripts/lib/roster.mjs`, shared with `scripts/http-inventory.mjs`).

The summary reports the share of `ALL_ENDPOINTS` with a specified 2xx response,
and the number of `x-unspecified` responses.

`--require-all` also fails when an endpoint has no specified 2xx response, or when
an `ALL_ENDPOINTS` path has no endpoint at all. It is off until the route-group
specifications land (P3–P10). P16 makes it the default.

## Malformed JSON bodies

Every route that reads a JSON body answers an unparseable body with the same
envelope, `400 VALIDATION_FAILED` (message `Body must be valid JSON`, or
`Invalid JSON body` on a few routes). It is not declared per route: a fixture
carries parsed JSON, so it cannot exemplify an unparseable body, and declaring
it on every route would force a fixture that cannot be written. Treat any JSON
route as also answering this 400.

## Rules for editing

- Declare a field only when the server sends it. Fixtures are transcribed from the
  handler, not invented.
- A fixture that changes the wire shape changes with it, in the same commit.
- Do not add `additionalProperties: true` to silence a finding. Use it only for
  objects whose keys are genuinely open, and say why in the group file's
  `description`.
- Do not use `x-unspecified` for a body you could describe. It is a visible debt,
  not a waiver.

## Shared machinery

`scripts/lib/conformance.mjs` holds the schema walking, `$ref` resolution, keyword
whitelist, validity, coverage and report used here and by
`scripts/conformance-agent-v2.mjs`. `scripts/lib/roster.mjs` holds the
`ALL_ENDPOINTS` parser.
